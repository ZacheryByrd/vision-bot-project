## 2026-10-08 (Task 1, made by Claude Code; review at Gate 1)
11. **The v2 robot model is a copy of the v1 xacro, not an include.** v1's diff-drive block must change (odometry on, odom TF off), xacro cannot delete a block from an included file, and v1's file must stay untouched. The spec allows "a copy or extension". Cost if wrong: v1 model changes must be mirrored by hand.
12. **A fourth twist_mux input, `idle` (priority 1), always publishes zero** (`vision_bot_nav/scripts/idle_stop.py`). twist_mux 4.3.0 forwards a command only from an input callback (checked in the installed `topic_handle.hpp`), and the Classic diff-drive plugin keeps executing its last command forever. Measured with `scripts/mux_check.py`: with only the three planned inputs, after every input stopped `cmd_vel` went silent and odometry still read 0.20 m/s (the robot drove on). With the idle input the robot stops once every real source has timed out. twist_mux is still the only publisher of `cmd_vel`. Cost if wrong: remove one node and one YAML entry.
13. **Caster height corrected in the v2 copy** (center z = -0.018 instead of v1's -0.02). v1's caster sits 2 mm below the wheels' contact point, pitching the robot nose-down by 0.025 rad; the tilted lidar then saw the floor about 3.3 m ahead as a wall (12% of scan returns, `scripts/scan_overlay.py`). After the fix: pitch 0.0000 rad at rest and 360/360 returns on modeled surfaces. v1 is unchanged (its camera does not care). Cost if wrong: none expected.
14. **Odometry from wheel encoders** (`odometry_source` 0). The plugin's default (1, "world") copies Gazebo's true pose into `/odom`, which would make raw odometry perfect and the Task 2 EKF comparison meaningless. Cost if wrong: one tag.
15. **Wheel frames from `robot_state_publisher`.** The Gazebo `joint_state_publisher` plugin publishes `/joint_states` and `robot_state_publisher` turns them into `base_link -> left_wheel/right_wheel`; the diff-drive plugin's own wheel TF stays off. One publisher per transform, and every robot-internal frame has the same owner. Cost if wrong: flip `publish_wheel_tf`.
16. **twist_mux params use the `/**` key.** A `twist_mux:` key matched only `/twist_mux`, so with `namespace:=robot1` the mux had no inputs (caught by `mux_check.py --namespace /robot1`). Cost if wrong: none.
17. **Keyboard teleop is not started by the launch file.** `teleop_twist_keyboard` reads keys from a terminal, and the image has no `xterm` to give it one. The launch file documents the one-line command for a second terminal (remapped to `cmd_vel_teleop`). Cost if wrong: add `xterm` to the image and a `teleop:=true` argument.
18. **The KDL "root link has an inertia" warning is kept.** It is inherited from v1's model and harmless (KDL only drops the root link's inertia for its own dynamics; Gazebo is unaffected). Removing it needs a new root frame such as `base_footprint`, which would change the spec's `odom -> base_link` frame contract. Cost if wrong: add `base_footprint` later and update EKF/Nav2 frame names together.
19. **Gate tools in `scripts/`:** `scan_overlay.py` (fraction of scan returns on the world's modeled surfaces, plus a PNG) and `mux_check.py` (scripted twist_mux phases judged on `cmd_vel` and odometry; reused at Gate 3 for "teleop overrides Nav2"). Pure logic is unit tested in `scripts/tests/`. Cost if wrong: none.

20. **Near-frictionless caster (mu 0.01) in the v2 model.** v1's caster is a rigid sphere with Gazebo's default friction (mu 1), so it is dragged sideways on every turn in place. 21. **Drive plugin track width = measured effective 0.186 m** (the wheel joints stay 0.16 m apart). Gazebo's cylinder-on-plane contact touches the floor at the wheels' outer rims. Spin tests with the plugin at 0.16 m: commanded 1.0 / 0.5 / -1.0 rad/s gave true rates 0.860 / 0.432 / -0.860 rad/s, a constant 0.86 = 0.16 / 0.186, while straight-line distance matched within 0.3%. ## 2026-10-14 (Task 6, made by Claude Code; review at Gate 6)
60. **`fleet_bridge` is an ament_python package in `ros2_ws/src/`** (#7) with tests in `test/` and flake8 at 100 columns, like the v1 package (the plan says `tests/`). The registration backoff, outage handling and telemetry timing live in `core.py`, a file the plan does not list, so they are unit tested without ROS; `bridge_node.py` is a thin ROS shell around it. Cost if wrong: none.
61. **HTTP uses the standard library (`urllib`) behind the plan's `HttpSession` interface.** `requests` is not in the container image, and adding it means an image rebuild for one dependency. Cost if wrong: a `requests`-based session is a drop-in replacement.
62. **HTTP runs on its own thread; every rclpy call stays on the executor thread.** HTTP calls block for up to 5 s, which would stall Nav2 action callbacks on a single-threaded executor. rclpy does not document its action client as safe to call from a second thread, so the fleet thread only queues goal sends and cancels and a 10 Hz timer carries them out. Cost if wrong: none.
63. **Robot identity and pose.** The bridge's `robot_id` is the fleet serial number (`VB-SIM-1`, `VB-SIM-2`), resolved to the fleet's integer id at startup; the robot's namespace is the node's ROS namespace (the plan's `namespace` parameter would duplicate it); the pose comes from `shared_pose` (#52), the robot's `map -> base_link` transform at 10 Hz, instead of a second TF listener. Cost if wrong: none.
64. **Goal handling.** The bridge takes the oldest pending goal. A newer goal cancels the active one, which is reported `canceled` at once. `accepted` is reported when Nav2 accepts the goal, not when it is sent. A goal Nav2 rejects, or that cannot be sent because `navigate_to_pose` is not up, is `failed`. Status reports are retried in order through an API outage; a report the API refuses (an error other than 401) is dropped with a warning. Cost if wrong: none.
